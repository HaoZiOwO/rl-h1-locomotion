# 最小人机耦合闭环 — phase-conditioned H1

> 状态：实验完成，sweep 数据补齐中。本文件是实验记录与边界声明的权威来源，数字以评估日志为准。
> 措辞纪律：数字自己说话，不做"数字+破折号+升华"模板。

## 0. 一句话总结

给 H1 平地行走策略加"外部节律输入"：观测注入相位时钟 [sin(2πφ), cos(2πφ)]，
奖励注入相位锁定的接触调度项（脚着地必须落在期望支撑窗内）。训练出的策略 =
跟随穿戴者节律的最小仿真原型。再用周期外力和相位突变测试"跟节律"与"抗扰动"。

## 1. 边界声明（面试先讲这一段，README 同步）

1. **信号通路级闭环，不是人体级闭环。** 相位信号是仿真内合成时钟（固定频率积分），
   不是 Daphnet 估计器的在线化输出。两者接口兼容=同为"当前步态相位"标量；Daphnet
   输出的是离散步态事件，中间需相位变量估计器（事件→连续相位 + 频率漂移跟踪），
   在线化列为下一步。
   本实验证明"相位信号 → 条件化策略 → 节律跟随"这条通路在仿真内成立。
2. **接触调度是人为设定的控制约束，不是数据检出。** 支撑窗（左足 φ∈[0,0.5)、右足
   φ∈[0.5,1)）是设计参数，reward 项是把"跟随节律"翻译成奖励函数。相位锁定率是
   训练目标达成度的度量，不是从数据里"发现"的规律。
3. **外力是理想正弦力。** 作用在 torso_link 的全局 +x 正弦力，模拟穿戴者上身随步态
   的周期性摆动干扰；不是穿戴者与机器人之间的真实交互力（pHRI 需要人体在环，纯仿真
   不可验证，本节未做）。
4. **对照的公平性。** 新旧策略评估用同一套受控配置（默认随机指令调度、无随机推搡、
   无 obs 噪声）；训练侧 PPO 配置与官方 h1_flat 完全一致（2048 envs / 1000 iter /
   128×3 网络 / seed 0），唯一变量 = +2 obs 维 + 1 reward 项。
5. **节律 vs 速度的关系。** v = 步频 × 步幅。时钟锁死步频 1.4 Hz 后，速度调节走步幅通道。
   在默认随机指令（0-1 m/s）下，指令跟踪误差 0.107 m/s —— 同协议实测 flat 基线为 0.068
   （§6 表 A=0 行），即**无外力下节律锁定有跟踪代价（~57%），外力下则保稳定 > 追命令**。
   注意：若同时**人为固定** 1.0 m/s 命令，会出现速度双峰
   （固定步频下大步幅/小步幅多吸引子，且固定命令在本版本与 heading 模式交互异常）——
   该现象属评估设定伪影，不进入结论（见 §4 方法论注）。

## 4. 评估一：稳态步态 + 相位锁定（eval_phase.py --mode steady，10 局，默认随机指令）

| 指标 | 值（mean±std） |
|---|---|
| 指令跟踪误差 track_err (m/s) | **0.107 ± 0.012**（H1 flat 官方评估参考 ~0.185，同口径） |
| 相位对齐分数 | **0.986 ± 0.002** |
| 左足着地频率 (Hz) | **1.425 ± 0.025** |
| 右足着地频率 (Hz) | **1.410 ± 0.020** |
| 存活率 | 1.00 |
| 平均奖励 | 48.2 ± 0.7 |

判读：着地频率 = 时钟频率（1.42 vs 1.40 Hz），对齐 98.6% —— **节律跟随成立**。指令跟踪
误差 0.107 m/s 高于同协议实测 flat 基线 0.068 m/s（§6 表）——节律锁定的跟踪代价，
外力下相位策略以跟踪精度换稳定性（见 §6）。

> 方法论注：早期版本用"固定 1.0 m/s 命令"评估，出现速度双峰（0.95/0.5 m/s）伪影。
> 排查发现固定命令在 isaaclab 0.54 与 heading 模式命令交互异常（官方 flat 策略同样
> 表现异常），且官方 eval 脚本的固定指令代码因属性名变更（velocity_command →
> base_velocity）静默失败回退随机指令。最终改为**默认随机指令调度**（两策略的训练
> 分布），度量改用与训练奖励同口径的逐帧指令跟踪误差。固定命令下的速度双峰数据
> 保留备查（phase_eval_steady.log），不进入结论。

## 6. 评估三：周期外力扫描（eval_phase.py --mode sweep，默认随机指令）

F(t)=A·sin(2π·1.4·t) 作用于 torso_link（全局 +x），A ∈ {0,50,100,200} N，20s/局，10 局。
基线 = 官方 h1_flat 规范检查点（seed 42，08-06_16-30-59）。外力频率 1.4 Hz 与步态时钟共振。

| A (N) | flat(seed42) 存活率 | flat track_err | phase 存活率 | phase track_err |
|---|---|---|---|---|
| 0 | 1.00 | 0.068 | 1.00 | 0.109 |
| 50 | 1.00 | 0.108 | 1.00 | 0.161 |
| 100 | 0.70 | 0.201 | **1.00** | 0.214 |
| 200 | 0.20 | 0.631 | **0.60** | 0.677 |

判读：
- **存活率是头号指标**：A=100 时 phase 全存活 vs flat 0.70；A=200 时 0.60 vs 0.20（3 倍）。
  **统计口径**：10 局/格——A=200N 的 6/10 vs 2/10、A=100N 的 10/10 vs 7/10，Fisher 精确
  检验单侧 p≈0.09/0.11，未达显著——"3×"是方向性信号而非显著结论。
  **机制假设未分离**："步态锁在时钟上吸收周期扰动"与"相位策略步态更保守（track_err
  更高，见本表）天然抗扰"两个假设都能解释存活率优势，本实验未做区分性对照。
  周期外力（同频共振）可被纳入步态周期吸收而非不可预期的随机扰动——此为机制假设之一。
- **跟踪精度是代价**：外力下 phase 的 track_err 略高于 flat（A=200 时 0.677 vs 0.631）。
  策略的取舍是"保稳定 > 追命令"——如实报告，不做"全面碾压"表述。
- 边界：200N ≈ 亚体重级周期扰动；外力是理想正弦力（见 §1.3）；10 局/格的统计口径。

## 8. 工程坑记录（本次实验踩的坑）

1. **Manager 构造期探测 obs/reward 维度**：ObservationManager._prepare_terms 会在 env
   __init__ 期间调用 obs 函数 → 自定义 env 状态必须用 cfg 里的 device/num_envs 先建
   占位 buffer，再在 super().__init__() 后换真值。
2. **carb 日志对重复警告限流 ~5s/条**：sweep 每步一次的 deprecation 警告被限流成
   5 秒一条，误判"一步 5 秒"两度误杀健康进程。真实 RTF ~0.3×（70ms/步，单 env 无 GUI
   正常水平）。判据教训：看业务输出（per-amplitude 汇总行），不看警告节奏。
3. **process kill 杀 bash 会连带杀 python 子树**（此前以为孤儿存活是误判——进程列表
   显示延迟）。判断"孤儿是否还活着"以日志文件 mtime 为准。
4. **flat 多 seed 有坏收敛**：seed 2 收敛到倒走步态（A=0 下 vx=-0.086）。基线必须用
   README 规范检查点（seed 42），不可用"最新目录"想当然。
5. **同进程内 env.close() 后重建 env 会挂死**（本次 22:23 实测）：sweep 先跑 flat 再跑
   phase 时，第二个 gym.make 的 env 创建阶段静默卡死（进程存活、无输出、无报错）。
   对策：不同策略的评估拆成独立进程跑（--sweep-policy flat / phase 分两次）。
6. **挂死的 Isaac 进程会堆积并拖垮后续新进程**：挂死进程占 ~2.4GB 显存不释放，
   后续 env 创建可能同样挂死。处置：powershell 按 CommandLine 过滤 `*eval_phase*`
   全量清杀，GPU 显存从 5.6GB 回落到 3.2GB 即干净。
