# DP 部署权衡：DDIM 少步采样（步数-延迟-性能）

- 基线：DDPM T=100（本实现为噪声项置 0 的确定性变体，非标准随机 DDPM，见 `eval_diffusion.py` 的 ddpm_sample）；DDIM η=0 均匀抽子步
- 延迟口径：单动作端到端采样墙钟（50 次均值，含 GPU 同步）；单次去噪网络前向 0.979 ms
- 性能口径：10 局确定性评估（seed 42+i），与官方 diffusion_vs_bc.md 同协议（走倒为止）

| 采样器 | 单动作延迟 (ms) | return | vs DDPM-100 |
|---|---|---|---|
| DDPM-100（基线） | 143.04 | 489.6 ± 27.5 | 100% |
| DDIM-100 | 174.30 | 474.3 ± 108.0 | 97% |
| DDIM-20 | 35.45 | 474.8 ± 139.4 | 97% |
| DDIM-10 | 18.41 | 538.8 ± 113.9 | 110% |
| DDIM-5 | 9.98 | 520.1 ± 102.5 | 106% |

> 统计注：DDIM-10 的 110%、DDIM-5 的 106% 在 std>100 下无统计意义，正文只采信"均值性能不降"；
> 方差放大指跨局标准差 102.5 vs 27.5（~3.7×，方差 ~14×）。

**结论**：
- 单次前向 0.98 ms × 步数 ≈ 延迟线性；DDPM-100 ≈ 143.0 ms/动作，当前 PyTorch eager 实现下 1 kHz（1 ms）实时预算不可行（未做 ONNX/TensorRT 优化）
- DDIM-10 降到 18.41 ms（性能 110%）；DDIM-5 9.98 ms（性能 106%）
- 剩余延迟仍需 chunking 摊销（一次推理出 k 步动作）——这正是 ACT 的设计动机，本项目 ACT 自实现见 results/act_vs_bc.md
